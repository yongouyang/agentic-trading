Strategy Signals & Trading Logic

When the strategy says BUY, does that mean you actually buy? (策略说BUY，就一定买入吗？) Strategy discovers opportunities. Signal is just a suggestion. Real trading must pass through risk control, order execution, fill confirmation, and account update.

Source: knowledge-base/day_19 (IMG_6623–IMG_6630), "30天学习量化投资 · Day 19: 策略信号与交易逻辑" · Extracted 2025-08-30

1Strategy's Job — Produce Signals, Nothing More

Strategy's task is simple: based on market data and indicators, determine what signal to produce (buy/sell/hold). It doesn't care about accounts, funds, or positions.

Strategy interface (Go)

type Strategy interface {
    // On each new Bar, return a Signal (or nil for no signal)
    OnBar(bar Bar, ind IndicatorSet, pos *Position) *Signal
}

Signal structure

type Signal struct {
    Symbol string    // instrument (e.g. "510300")
    Side   Side      // BUY / SELL / HOLD
    Time   time.Time // when signal was generated
    Note   string    // optional remark
}
💡 Strategy discovers opportunities (produces signals), not executes trades. Signal is the strategy's "suggestion" — whether it gets executed is decided by the subsequent modules. (Strategy 发现机会（产生信号），而不是执行交易。)

2Dual MA Signals — Golden Cross & Death Cross

Capture the moment of state change — not the state itself. Use edge-triggered detection to avoid duplicate signals.

exampleGolden cross (BUY) & death cross (SELL)

Golden cross (BUY signal)

Short MALong MARelationship
Yesterday (t−1)10.811.010.8 ≤ 11.0
Today (t)11.211.111.2 > 11.1 → BUY

Condition: yesterday short ≤ long AND today short > long

Death cross (SELL signal)

Short MALong MARelationship
Yesterday (t−1)11.611.211.6 ≥ 11.2
Today (t)10.911.110.9 < 11.1 → SELL

Condition: yesterday short ≥ long AND today short < long

State machine prevents duplicates

IN_DOWN
short ≤ long
waiting for golden cross
→ BUY
IN_UP
short > long
waiting for death cross
→ SELL
IN_DOWN
back to waiting
💡 The signal comes from the state transition. Strategy must remember the previous bar's relationship. Only when it changes does a signal fire. The first tradeable bar usually has no signal (no previous state to compare). (信号来自"状态切换"。)

3Signal Is a Suggestion, Not a Guarantee

Signal is like a navigator saying "turn left ahead" — but whether you actually turn depends on road conditions, speed, rules, and fuel.

conceptSignal → Order → Trade — three different things

Signal (建议)

"I think we should buy"

Strategy's opinion. Contains: symbol, direction, time, note.

Order (计划)

"Prepare to buy X shares at Y price"

Execution plan with quantity, price, order type.

Trade (成交)

"Actually bought Z shares at W price"

Market's real fill result with actual price, quantity, fees.

Same Signal, different outcomes

✓ Cash sufficient

Order placed → filled (partially or fully).

✗ Cash insufficient

Order rejected — no fill.

✗ Position limit reached

Risk rejects — no order generated.

✗ Market halted / limit-up

Cannot trade — no fill.

⚠ Large slippage

Order placed, but fill price much worse — fewer shares filled.

💡 Strategy has decision authority, but no account modification authority. Signal is just the strategy's idea — real trading requires passing through risk control, order generation, fill execution, and account update. (策略有决策权，但没有账户修改权！)

4BUY Execution — Can We Actually Buy?

A BUY signal just means "want to buy". Whether you can buy, how much, and when — is decided by the execution and risk layers.

checksBUY decision checklist

1
Cash sufficient? — Available cash ≥ buy amount + estimated fees?
2
Position limit? — Current position + planned position ≤ max position?
3
Risk control triggered? — Max drawdown, single-stock risk, volatility limits?
4
Trading restrictions? — Trading hours? Halted? Limit-up?
5
Strategy constraints? — Already holding? Duplicate signal?

All pass → generate Order. Any fail → no Order, or adjust quantity / defer.

5SELL Execution — Can We Actually Sell?

SELL signals are also suggestions. Whether you can sell, how much, and when — same multi-layer decision.

checksSELL decision checklist

1
Have a position? — No position → SELL signal ignored.
2
Quantity valid? — 0 < sell qty ≤ current holding.
3
Risk/stop-loss rules? — Any active stop-loss or risk rules blocking the sale?
4
Trading restrictions? — Halted? Limit-down? Trading hours?
5
Strategy constraints? — Cooldown period? Minimum holding days?

Common SELL signal scenarios

Death cross

Dual MA death cross triggers SELL.

Take-profit target

Profit target reached → suggest selling.

Stop-loss triggered

Loss exceeds threshold → suggest selling.

Trend reversal

Strategy detects reversal → suggest selling.

6Responsibility Boundaries — Want → Can → Did

Each module has a clear role. No module may overstep its authority. (想买 → 能买 → 买到)

chainModule responsibilities

ModuleCore jobMust NOT doOutput
StrategyDiscover opportunities, produce SignalDecide quantity, modify accountSignal
RiskCheck funds, positions, risk; compute allowed qtyPlace orders, execute tradesQuantity
OrderConvert to specific order (qty, price, type)Guarantee fill, modify accountOrder
BrokerSend order to market, get fill resultDecide strategy or riskTrade
PortfolioUpdate cash, positions, record P&LChange historical trade resultsAccount state

💡 Common errors (overstepping):
  • Strategy directly deducting cash or adding positions
  • Skipping risk checks and placing orders
  • Duplicate orders causing position blowout
  • Ignoring fill reports — account state drifting from reality
Every account change must originate from a Trade (fill report).

7The Complete Trading Chain — 8 Steps

From a single K-line to the final account change — 8 key steps, each with distinct responsibilities, all indispensable.

chainFull pipeline

#StepCore questionInput → OutputExample
1BarWhat happened in the market?Raw data → Bar2024-05-20 Close=10.02
2IndicatorWhat are the indicator values?Bar → indicator valuesSMA5=10.15, SMA20=9.85
3StrategyWhat do I think we should do?Indicators → SignalSignal{BUY, 510300}
4SignalTrading suggestionStrategy → SignalBUY 510300 @ t
5RiskHow much can we buy/sell?Signal + account → QtyCan buy 5,000 shares
6OrderWhat to trade?Signal + Qty → OrderBuy 5,000 @ MKT
7BrokerWhat did the market fill?Order → TradeFilled 4,980 @ 10.02
8PortfolioWhat changed after the trade?Trade → account updateCash −50,019.6, Pos +4,980

Pseudocode: one complete BUY flow

bar  := data.NextBar()              // 1. Bar
ind  := sma.Update(bar)             // 2. Indicator
sig  := strategy.OnBar(ind)         // 3. Strategy

if sig.Side == BUY {               // 4. Signal
    qty := risk.Check(sig, portfolio) // 5. Risk
    if qty > 0 {
        order := NewOrder(sig.Symbol, BUY, qty, MKT) // 6. Order
        trade := broker.Buy(order)                    // 7. Broker
        portfolio.Update(trade)                       // 8. Portfolio
    }
}
★Every step from Bar to Portfolio matters — none can be skipped. Pay attention to "state changes", respect uncertainty, and you'll build a robust quant trading system. (从Bar到Portfolio的每一步都很重要，缺一不可！)

Strategy has suggestion authority but no account modification authority. Signals are just suggestions. Real trading must pass through risk control, orders, fills, and account updates. Clear responsibilities + stable system = long-term operation.
