Time Series & Arrays — Computing MA with a Sliding Window

A program doesn't see a candlestick chart — it sees a time series: an array of numbers in time order. From today we understand the market with code, not with our eyes. (程序看到的不是K线图，而是时间序列。从今天开始，我们用代码理解市场，而不是用眼睛看图形。)

1The Essence of Market Data: a Time Series

What a quant program processes is not a chart, but a sequence of numbers ordered by time (行情数据的本质：时间序列).

What we see (图形)

A candlestick (K-line) chart — intuitive and easy to read, but a computer cannot process graphics directly. The chart is only a visualization of the underlying data.

What the program sees (数据)

A plain array of numbers — each number is the closing price at one point in time:

// Go example: closes for Day1..Day7
close := []float64{10, 11, 12, 13, 14, 15, 16}

Four properties of a time series (时间序列的特点)

1

Time-ordered

Data must be arranged from earliest to latest (按时间从早到晚排列).

2

One-dimensional

Just a string of numbers — no rows and columns (没有行和列的概念).

3

Continuously varying

Adjacent time points are usually correlated (相邻时间点的数据通常是相关的).

4

Iterable

Can be processed one by one, from head to tail (可迭代计算，逐个处理).

Why it matters

Every indicator (e.g. MA), every signal, every strategy is ultimately computed day by day from this string of numbers (所有指标、所有信号、所有策略，最终都是基于这串数字逐日计算出来的).

2The MA Computation Window: Only the Last N Prices

MA is a sliding window (移动平均 / 滑动窗口) that always uses only the most recent N closing prices.

Core concept: MA5 always looks at only the most recent 5 prices, forming a window of length 5. Each time the window moves forward one day, the oldest data point is discarded and the newest is added. (MA5 永远只看最近 5 个价格；窗口每向前移动 1 天，就丢弃最老的数据，加入最新的数据。)

What is the MA5 window?

Price series (closes)10 · 11 · 12 · 13 · 14 · 15 · 16 · 17 …
MA5 window (last 5)10 · 11 · 12 · 13 · 14
MA5 formulaMA5 = (10+11+12+13+14) / 5 = 12

✓ Window properties (窗口特点)

  • Fixed length — always exactly 5 prices (长度固定).
  • Only the recent — never looks at older data (只看最近).
  • Slides daily — moves forward 1 day at a time (每天向前滑动).
  • Real-time updates — reflects the latest trend (实时更新).

💡 Why "recent"? Because we care about the short-term trend. If prices from long ago were included, old data would "dilute" the result and the MA would lose sensitivity to the current market (被旧数据"稀释"，失去对当前市场的敏感度).
★The MA window contains only the last N closes — a sliding window moving forward day by day. Remember: MA is not a cumulative average; it describes the recent price level (MA 不是累计平均，而是描述"最近"的价格水平).

✓ Correct: sliding window (last 5)

  • Window size fixed at 5; each new data point shifts the window by one.
  • Always keeps only the most recent 5 prices.
  • Reflects the recent trend and responds quickly to change.

✗ Wrong: cumulative average (all history)

  • If the window never moves and all history keeps accumulating, you get a cumulative average.
  • It cannot reflect the "recent" price level or trend.
  • Slow to react, blind to recent change (反应迟钝，无法体现近期变化).
★The essence of MA is a fixed-size sliding window. Window movement = discard the oldest data + add the newest data (窗口移动 = 丢弃最旧数据 + 加入最新数据).

4Why Not Include All Historical Data?

Averaging all history yields a cumulative average — lagging, distorted, and overweighted toward the distant past.

✓ Correct: only the last N (e.g. MA5)

Series: 10 11 12 13 14 15 16 17 … — window is the last 5:

MA5 = (13+14+15+16+17) / 5 = 15
  • Reflects only the recent price level (只反映最近的价格水平).
  • More sensitive to new data, follows the trend in time.

✗ Wrong: cumulative average over all history

Including every price ever seen:

Cumulative avg = (10+11+12+…+17) / 8 = 13.75
  • Sluggish — cannot show recent change (反应迟钝).
  • Distant data gets too much weight and masks the recent trend (远期数据权重过大，掩盖近期趋势).

Why fix N at 5?

  • 5 is a common empirical value that balances the trade-off: too small → noisy, frequent whipsaws (噪音大，波动频繁); too large → slow response, heavy lag (反应慢，滞后严重).
  • Different strategies use different windows: 5, 10, 20, 60, …

💡 The program only emits indicator values once data is sufficient — no MA5 for the first 4 days, avoiding false signals from incomplete data (前 4 天不产生 MA5，避免使用不完整数据导致错误信号).
// Go example: computing MA5
func MA5(prices []float64) float64 {
    if len(prices) < 5 {
        // insufficient data — cannot compute
        return math.NaN()
    }
    sum := 0.0
    n := len(prices)
    for i := n - 5; i < n; i++ {
        sum += prices[i]
    }
    return sum / 5
}

✗ Common mistakes (常见错误)

  • Mistake 1: averaging all historical data → you get a cumulative average, not a moving average.
  • Mistake 2: forcing the calculation with insufficient data → wrong MA values and false signals (虚假信号).
  • Mistake 3: array index out of bounds (数组越界) → crash or runtime errors.

✓ Correct practices (正确做法)

  • Only the most recent N data points participate in the computation.
  • Return an empty value or NaN when data is insufficient.
  • Make sure index ranges are correct.
  • Indicator values exist only from day N onward (从第 N 天开始才有指标值).
★When data is insufficient: don't guess, don't compute, don't output — that itself is a form of risk control (数据不足时，不猜、不算、不输出，这本身就是一种风险控制). The first step of computing any indicator is ensuring enough data; without it, all calculations and signals are meaningless.

6Computing MA Efficiently: the Sliding-Window Algorithm

Re-summing every time costs O(N) per step; the sliding window makes each update O(1) (滑动窗口算法).

✗ Wrong: re-sum the whole window each day

  • Every day, all 5 numbers in the window are added up again from scratch.
  • With large windows (100, 200), the workload becomes huge.
  • Time complexity: O(N) per update.

✓ Right: sliding window — "add new, subtract old" (加新减旧)

  • Each step does only two things: add the new data, subtract the old.
  • The window sum needs one addition and one subtraction.
  • Time complexity: O(1) per update.
  • Ideal for real-time computation and large-scale backtesting.

Go implementation: the MA struct with an Update method

type MA struct {
    window []float64 // holds the most recent N values
    sum    float64   // sum of the values inside the window
    n      int        // window size N
}

func NewMA(n int) *MA {
    return &MA{window: make([]float64, 0, n), n: n}
}

func (m *MA) Update(v float64) (float64, bool) {
    // 1. add the new data
    m.window = append(m.window, v)
    m.sum += v
    // 2. if the window exceeds N, drop the oldest value
    if len(m.window) > m.n {
        old := m.window[0]
        m.window = m.window[1:]
        m.sum -= old
    }
    // 3. fewer than N values — cannot compute yet
    if len(m.window) < m.n {
        return math.NaN(), false
    }
    // 4. compute and return the MA
    return m.sum / float64(m.n), true
}

7Day 5 Summary — Core Takeaways

Today we completed the key step of MA computation: efficiently computing moving averages with a sliding-window algorithm.

  • The essence of the window — MA only cares about the last N prices, forming a fixed-size sliding window (窗口的本质).
  • Window movement — each new price pushes out the oldest and brings in the newest; the window slides forward by one (窗口的移动).
  • Why not all history — a cumulative average over all history lags and distorts; only the recent N reflect the current trend.
  • Sliding-window algorithm — O(1) per update (one add + one subtract) versus O(N) for recomputation.
  • Insufficient data — the first N−1 days produce no value; data sufficiency must be guaranteed.

✓ Sliding-window algorithm (recommended)

  • Time complexity: O(1)
  • Per update: 1 addition + 1 subtraction
  • Suits real-time computation and large-scale backtests
  • High performance, low memory footprint

✗ Recompute-from-scratch algorithm (inefficient)

  • Time complexity: O(N)
  • Per update: N additions
  • Slow on large data; unsuitable for real-time scenarios

Practical notes for real trading (实战中的注意事项)

  • Use float64 — avoid integer division.
  • Mind price adjustment for corporate actions (前复权 / 后复权).
  • During trading hours, only use completed K-line (bar) data.
  • Multiple indicators can share the same price stream for efficiency.
  • Handle boundaries carefully — no out-of-range indexes or empty windows.
