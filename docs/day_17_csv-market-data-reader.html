CSV Market Data Reader & io.Reader Design

The first gate of a quant system: don't let dirty data enter the backtest. (量化系统的第一关：别让脏数据进入回测。) No matter how good the strategy, if the data is wrong, the results are wrong.

2Why io.Reader? — Decoupling Data Sources

io.Reader is Go's core interface. Any data source can become an io.Reader, so the parser doesn't care where data comes from.

designThe real reason for io.Reader

Common misunderstanding

"io.Reader is just for memory efficiency — only big files need streaming; small files can just read into memory."

The real reason

Decoupling data sources. Whether data comes from files, HTTP, Kafka, S3, or memory — the parser doesn't need to know. It only focuses on parsing. (不管数据来自文件、网络还是消息队列，解析器都不需要关心，它只专注于解析。)

3Two-Layer Interface: Reader + Loader

Separate "how to get data" from "how to parse data" — cleaner interfaces, simpler tests, better reusability.

designLayer responsibilities

Reader layer — core parser (ReadBars)

  • Input: any io.Reader
  • Job: row parsing, field validation, type conversion, time-order checking
  • Output: []Bar or error
func ReadBars(r io.Reader) ([]Bar, error)

Loader layer — data fetcher (LoadBarsFromCSV)

  • Job: open the file (or other source)
  • Calls: ReadBars for actual parsing
  • Extensible: future LoadBarsFromHTTP, LoadBarsFromS3…
func LoadBarsFromCSV(path string) ([]Bar, error) {
    f, err := os.Open(path)
    if err != nil { return nil, err }
    defer f.Close()
    return ReadBars(f) // the key decoupling
}

Benefits of layered design

Single responsibility

Each interface does one thing — logic is clearer.

Easy testing

Reader can use strings.Reader / bytes.Buffer for unit tests.

Reusable

Reader works with HTTP, S3, Kafka — any io.Reader source.

Extensible

Adding a new data source = new Loader only — Reader unchanged.

4Reader Responsibility Boundaries

The Reader is a "data quality inspector" — it only converts raw data into clean, reliable, usable Bars. Nothing more.

boundaryWhat Reader should / should not do

✓ Should do

  • Parse format — parse CSV line by line
  • Validate fields — check headers, field count, required fields
  • Type conversion — string → float64, int64, time.Time
  • Logic validation — price ranges, High/Low relationships
  • Time order check — strictly ascending, no duplicates
  • Convert to Bar — generate unified internal Bar structure
  • Return clear errors — include line number and reason

✗ Should not do

  • Fill missing data — don't auto-fill gaps
  • Guess / infer — don't guess missing values
  • Auto-fix — don't silently fix bad data
  • Trading decisions — no buy/sell logic
  • Cash/position handling — no account logic
  • Performance tricks — no caching or concurrency in Reader
  • Storage — don't persist to database or cache

✗ Wrong: Reader oversteps

// Auto-filling missing dates (WRONG!)
for date := start; date <= end; ... {
    if !hasData(date) {
        bars = append(bars, fillBar(date))
    }
}
// Making trade decisions (WRONG!)
if bars[i].Close > ma {
    // generate buy signal
}

✓ Right: clear boundaries

bars, err := ReadBars(reader)
if err != nil { return nil, err }
// Reader returns clean Bar list only
// Strategy/backtest/risk handle the rest
signals := strategy.Generate(bars)
trades  := backtest.Run(signals, bars)

5Data Quality Checklist — The First Line of Defense

Prefer explicit errors over silently "fixing" data. (宁可明确报错，也不要"聪明地"偷偷修数据。)

validationMust-error conditions (必须报错)

CheckConditionsExample problem
File/headerEmpty file, header-only, wrong columnsdate,symbol,open,high,low,volume (missing close)
Field basicsEmpty symbol, empty fields, wrong field count2026-07-28,,4.12,4.18,4.09,4.16,123
Date formatWrong format, parse failure2026/07/28 (must be YYYY-MM-DD)
Numeric parseNon-numeric values, illegal charactersclose = "abc"
Value reasonablenessPrice ≤ 0, Volume < 0open = -1.00 or volume = -100
OHLC logicHigh < Low, Open/Close outside [Low,High]High=4.05, Low=4.09
Time orderTime reversed, duplicate dates07-29 → 07-27 (going backward)

Acceptable conditions (不需要报错)

Weekends & holidays missing

CSV records trading days only — no natural-day continuity required.

Non-consecutive but ordered dates

E.g., 07-31 → 08-03 (skips weekend). Strictly increasing is sufficient.

Volume = 0

No trading or data gaps — still valid in some markets.

Decimal prices

E.g., 10.32, 0.1234 are all legal.
