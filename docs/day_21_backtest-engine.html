Backtest Engine — The System Orchestrator

Who makes the entire quant system run? From data to performance, how do all modules collaborate? Today we build the system's "master dispatcher" — the Backtest Engine. (谁来让整个量化系统跑起来？)

Source: knowledge-base/day_21 (IMG_6639–IMG_6646), "30天学习量化投资 · Day 21: Backtest Engine" · Extracted 2025-08-30

1What is Backtest? — A Flow Dispatcher, Not a Strategy

Backtesting is simulating a trading system end-to-end on historical data to see "what if we had done this". The Backtest Engine is the dispatcher — it doesn't produce trading ideas or decide buys/sells.

conceptThe Engine as Director

Think of the Engine as a director (导演). It decides "when it's each actor's turn on stage" — but never acts for them. The Strategy, Broker, Portfolio, and Performance are the actors; each does their own job. (Engine像导演，决定"什么时候轮到谁上场"，但不替演员演戏。)

What the Engine solves

  • Which historical data? From what date to what date?
  • At what frequency? (1-minute / daily / weekly bars)
  • At each time point, which modules should work?
  • How are generated orders handled? How is the account updated after fills?
  • How are the final results evaluated?
💡 Engine controls flow ≠ business logic. Modules each handle "what to do"; Engine handles "when to do it and in what order". (模块各自负责"做什么"，Engine 负责"何时做、按什么顺序做"。)

💡 Time ordering is critical. Signal is generated at time T, but the actual fill typically happens at T+1's open price. Wrong ordering causes: look-ahead bias (未来函数), duplicate fills, incorrect drawdowns, unrealistic returns.

4Engine's Responsibilities — Orchestrate, Don't Decide

The Engine is like a conductor — it doesn't play any instrument, but decides who plays when.

roleWhat the Engine does

  • ① Traverse market data in time order, bar by bar
  • ② Call Strategy with latest bar data, receive Signal
  • ③ Process order flow — convert Signal to Order
  • ④ Update Portfolio based on Trade results
  • ⑤ Record all key data — orders, trades, positions, equity curves
  • ⑥ Output Performance — compute return, drawdown, Sharpe, etc.

What the Engine does NOT do

  • ✗ Does not decide when to buy or sell (Strategy's job)
  • ✗ Does not compute indicators or strategy logic
  • ✗ Does not decide position size or stop-loss rules (Strategy/Risk)
  • ✗ Does not modify fill prices (Broker's job)
  • ✗ Does not directly manipulate account data (Portfolio's job)
  • ✗ Does not output strategy conclusions (only objective results)

5Go Implementation — Engine Struct & Run()

Engine holds dependencies (components), not business logic. It's the "director" that controls flow.

goEngine struct

type Engine struct {
    Strategy  Strategy    // generates trade signals
    Broker    Broker      // executes orders, simulates fills
    Portfolio *Portfolio   // manages positions, cash, equity
    Perf      *Performance // records & computes metrics
    Data      DataFeed    // market data source
    Config    Config      // initial capital, fee rates, etc.
    Logger    *log.Logger  // logging
}

Run() pseudocode — the main loop

func (e *Engine) Run() error {
    e.Logger.Info("backtest start")

    for e.Data.HasNext() {
        bar := e.Data.Next()          // 1. Get next Bar
        e.Now = bar.Time

        signal := e.Strategy.OnBar(bar)  // 2. Strategy processes Bar → Signal

        if signal != nil {
            order := signal.ToOrder()       // 3. Signal → Order
            trade := e.Broker.Execute(order, bar) // 4. Broker fills → Trade
            e.Portfolio.ApplyTrade(trade)  // 5. Update Portfolio
        }

        e.Perf.Record(bar, e.Portfolio)  // 6. Record snapshot
    }

    result := e.Perf.Calculate(e.Portfolio) // 7. Compute final performance
    e.Logger.Info("backtest end")
    return result
}
💡 Engine only holds dependencies, not logic. It's the "conductor" — controlling flow without playing any instrument. Changing strategies or brokers requires zero changes to the Engine. (Engine像一条精确的流水线，把每个模块串起来，按正确的时间顺序工作。)

★Day 21 Summary

✗ Wrong: all logic in Engine

  • Engine contains buy/sell conditions
  • Engine computes fees, slippage
  • Engine updates cash and positions
  • Engine grows to thousands of lines
  • Changing a strategy means changing Engine
  • Hard to test, debug, or reuse

✓ Right: modules handle their own jobs

  • Engine only dispatches flow
  • Strategy only produces Signals
  • Broker only handles fills
  • Portfolio only manages accounts
  • Performance only computes metrics
  • Clean, extensible, testable, reusable

Why this design?

Module decoupling

Each module is independent — no internal cross-dependencies.

Easy to extend

Swap strategies, brokers, or add risk control trivially.

Easier to test

Every module can be unit-tested in isolation.

Reusable

Modules work across different strategies and instruments.

★Backtest Engine is the "director" of the entire system — letting Strategy, Broker, Portfolio, and Performance each do their own job, collaborating in the correct time order, ultimately turning a stretch of history into evaluable investment performance. (Backtest Engine 是整个系统的"导演"，让各"演员"各司其职，按正确的时间顺序合作，最终把一段历史变成可评估的投资绩效。)

Engine decides "when to call whom" — not "why to trade". (Engine 决定"什么时候调用谁"，不决定"为什么买卖"。)
